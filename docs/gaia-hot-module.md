# Gaia code module — first click-to-update slice

The renderer references only `module-contracts/SceneModules.Contracts.csproj`. Gaia code is built separately from `modules/GaiaPresence/GaiaPresence.Module.csproj`; the renderer does not reference that assembly at compile time. Each loaded image gets a collectible `AssemblyLoadContext`, sharing the contract assembly with the host. This is trusted local code, not a sandbox for untrusted plugins.

Build V1 with `dotnet build modules/GaiaPresence/GaiaPresence.Module.csproj -c Release -p:Version=1.0.0 -o <v1-directory>`; build V1.1 with `-p:Version=1.1.0 -p:DefineConstants=GAIA_V11 -o <v11-directory>`. V1.1 adds executable geometry code (an accent collar), not just a version string. Place only the module DLL in `<scene-output>/modules/gaia/initial/` for V1 and `available/` for the candidate. The DLL's real assembly version and SHA-256 drive the displayed version and loaded-image receipt. Availability inspection reads PE metadata without running candidate code.

The lower 3D version/candidate plaque is clickable. A click queues the exact advertised hash; `Advance` stages code and Vulkan resources at a frame boundary, waits for the GPU before retiring the old mesh, and requests unloading of the old code context. A missing/changed/invalid candidate, failed allocation or failed fence keeps the existing code and surface. No update runs automatically on the live listener. Blue/green are fixed slot identities; labels also state active/candidate/retired. A retired version is **not** a rollback button in this first slice.

CPU tests are in `module-tests` and use real V1/V1.1 DLLs; only the graphics-resource port is simulated there. `Link.SelfTest` also checks language changes and the 3D click projection. The scene's strict NuGet lock adds only the local contracts project, with package pins preserved.

Real Vulkan proof used `--demo --module-click-test --hidden --quality flat --cap 10 --seconds 11 --module-dir <isolated-package> --shots <proof-directory>`. This test-only flag requires both `--demo` and `--shots` and is refused on a live listener. The simulated click uses the same projected hit-test/queue as the mouse callback.
